# IUsage

在 Windows 11 任务栏和 macOS 菜单栏上显示 Claude 或 Codex 的用量：上面一条是 5 小时窗口，下面一条是 7 天窗口。

| | Windows 11 | macOS 13+ |
|---|---|---|
| 形态 | 嵌入任务栏的小组件，托盘图标兜底 | 菜单栏项目 |
| 产物 | 单个 exe，约 425 KiB（含应用图标），无运行时依赖；此前实测常驻内存约 4 MB（私有） | `IUsage.app`，主程序约 660 KiB；尚无可靠的 CPU / 内存测量 |
| 分发 | 自行构建，exe 无代码签名 | 自行构建，仅本机 ad-hoc 签名，未公证 |
| 实现 | Rust，`src/` | Swift（AppKit）+ 复用 `src/` 的 Rust 核心，`macos/` |

下面的截图是 Windows 版；Mac 版的界面说明和构建见 [`macos/README.md`](macos/README.md)。

![任务栏上的进度条](docs/screenshots/claude.png)

![详情面板](docs/screenshots/panel.png)

前提：本机装有 Claude 或 Codex 的桌面端（或 Claude Code / Codex CLI）并已登录。程序读它们留在本机的登录凭据，自己不需要登录。

Claude 要注意：桌面端有自己的登录，不会更新 `~/.claude/.credentials.json`，程序读的是这个文件，它来自 Claude Code 命令行的登录。这个文件里的访问令牌约 8 小时过期，过期后程序会用文件里的刷新令牌自行续期（见“数据来源”）；只有刷新令牌也失效时，才需要在终端运行一次 `claude` 并输入 `/login`。

## 使用

下面是 Windows 版。Mac 版的操作大体一致，差异见本节末尾。

把构建出的 `iusage.exe` 放到一个只有你自己能写的本地文件夹里运行（原因见“安全上要知道的”）。

- **切换 AI**：点击进度条左边的字母（橙色 `C` = Claude，蓝色 `X` = Codex），或右键菜单里选。
- **详情面板**：左键点进度条（字母和手柄以外的地方）或托盘图标。面板同时列出 Claude 和 Codex，带精确的重置时间和数据的新旧；再点一次、点别处或按 Esc 关闭。面板开着的时候，另一个 AI 的数据如果过期了也会顺带刷新。
- **移动位置**：按住最左侧的点阵手柄横向拖动，位置会记住。
- **右键菜单**：切换 AI、显示已用 / 显示剩余、立即刷新、低额度提醒、开机自启、退出。
- **低额度提醒**：当前显示的那个 AI，已用量到 75% 和 90% 时各弹一次系统通知；同一个窗口内不重复，窗口重置后重新生效。默认开启，在右键菜单里关。
- **开机自启**：在右键菜单里勾选。它记录的是 exe 当前所在的路径；移动 exe 之后勾选会消失，重新勾一次即可。
- **托盘图标**：同样的两条进度条，鼠标悬停看摘要，左键开详情面板，右键出菜单；任务栏嵌入失败时靠它兜底。
- 进度条颜色按已用量变化：75% 起变黄，90% 起变红。
- 右侧文字是“百分比 + 距离重置的时间”，例如 `13% 4h`。

**Mac 版的差异**（需要 macOS 13 或更高）：

- 点击字母（`C` / `X`）切换 AI，点其余部分打开详情面板；右键或 Control 点击出菜单：切换 AI、显示已用 / 显示剩余、立即刷新（冷却期间是灰的）、低额度提醒、登录时启动、退出。
- 没有拖动手柄，位置由系统菜单栏决定；也没有托盘图标。
- 低额度提醒和登录时启动**默认关闭**（Windows 版的提醒默认开启）。提醒开启时才会申请系统通知权限，阈值同为 75% / 90%；登录时启动用系统的登录项接口，需要先把 app 放到“应用程序”里再勾选。
- 刷新节奏、最小间隔、限流退避、空闲降频的规则和 Windows 版相同，实现共用同一份 Rust 代码。缓存在 `~/Library/Application Support/IUsage/cache.json`。
- 本地登录凭据有问题时（未登录、已过期、钥匙串读不出、格式异常）会像 Windows 版一样变暗并写明原因，每隔一会儿重查本地存储，不发请求，也不弹钥匙串授权框。

状态文字：

| 显示 | 含义 |
|---|---|
| `…` | 正在取数据 |
| `未登录` | 没找到登录信息，需要先登录对应的客户端（Claude 要登录 Claude Code 命令行） |
| `已过期` | 登录已过期且无法自动续期（没有刷新令牌、刷新令牌也过期，或被服务端拒绝）。Claude：在终端运行 `claude` 并输入 `/login`；Codex：在 Codex 里重新登录。换了新登录后，一般几秒内自动恢复；如果刚被服务端拒绝过，要先等完 5 分钟的退避 |
| `无法保存` | 无法安全保存到 `~/.claude/.credentials.json`（只读或被占用）。检查文件权限；程序在请求前就会检查，所以不会白白用掉刷新令牌 |
| `离线` | 网络不通，检查代理 |
| `限流` | 请求太频繁被服务端拒绝（HTTP 429），至少等 5 分钟后自动重试；这期间“立即刷新”是灰的 |
| `HTTP 5xx` 等 | 服务端返回了其他错误码，自动重试 |
| `错误` | 返回内容无法识别，多半是接口变了 |
| 整体变暗 | 最近一次刷新失败，显示的是之前的数据。其中已经重置过的窗口不再显示 `0%`（重置后用没用过是不知道的），而是显示当时的错误状态 |

出错后会自动重试。普通网络/服务错误的退避从 30 秒起逐次加倍，但实际请求仍至少间隔 2 分钟；限流或凭据被服务端拒绝时按 5、10、16 分钟退避。服务端要求更长等待时完整遵守，不截短 Retry-After。只有本地凭据缺失，或过期而又无法续期时，才每 15 秒重新检查文件，不发送请求。

`%APPDATA%\IUsage\` 下有三个文件：

- `settings.json`：设置。其中 `warn_pct`（默认 75）和 `crit_pct`（默认 90）是变黄 / 变红和提醒的阈值，`poll_secs`（默认 180，最小 30）是刷新间隔，这三项没有菜单，直接改文件后重启程序生效。刷新间隔不建议调小：Claude 的接口会限流，一旦触发要十分钟以上才恢复。
- `cache.json`：两家各自最近一次成功取到的数据、提醒记录、请求时间和退避状态。重启后先显示缓存；新数据和仍未结束的等待均会阻止重复请求。缓存和设置采用临时文件替换，避免写到一半损坏原文件。
- `last-error.txt`：最近记录的失败原因；相同错误不重复写入，文件修改时间是这条错误最近一次被写入的时间。

## 数据来源

### Windows 0.1.2：Claude 数据来源与网页登录

0.1.3 更新：确认网页登录失效（HTTP 401）后，保留上次额度，提醒一次并暂停网页请求。该状态跨重启保存；403 访问受阻、429 限流不会被误判成登录失效。点击失效通知、详情面板的“更新网页登录…”（也支持 Enter）或右键菜单的失效入口即可更新。更新窗口保留组织 ID、留空失效的 key；保存新登录后按原有等待和刷新间隔恢复，不额外发送验证请求。操作系统可能抑制通知，面板和菜单入口始终可用。

右键任务栏小组件或托盘图标 → **Claude 数据来源**：

- **Claude Code 登录**：读取已有的 Claude Code 凭据。
- **Claude 网页登录**：使用本机已加密保存的网页 sessionKey；尚未配置时自动打开配置窗口。
- **配置 / 更新网页登录…**：密码框默认隐藏，支持纯值或 `sessionKey=值`，带“如何获取？”和“打开网页”按钮。组织 ID 在高级设置中，通常留空；多个组织时需指定。

点击“保存并使用”后，在下一次允许刷新时使用网页渠道，不为验证配置额外请求 API。登录失效后从同一入口更新；“清除登录信息”会删除本机加密副本并切换回 Claude Code。

登录信息通过 Windows 当前用户 DPAPI 加密，保存在 `%APPDATA%\IUsage\claude-web.dpapi`，普通设置仅保存渠道选择。不会读取浏览器数据库，也不会把 sessionKey 写入日志。不要分享 sessionKey。

两个渠道共用持久化的 Claude 限流门禁。切换、更新、清除配置都不重置已有等待；旧渠道在途结果不会显示成新渠道数据。网页每轮仅查询组织和额度，指定组织后仅请求额度；失败不会立即切换 OAuth 追发请求。

已有环境变量配置仍兼容，直到用户在菜单中明确选择渠道。菜单选择优先于旧环境变量，无需重启。

续期仅在 HTTP 400/401 且 `error` 为 `invalid_grant` 时停止重试同一刷新令牌；其他 HTTP 续期失败保留凭据并退避。面板显示上次成功来源、时间和等待截止时间。所有新流程均使用离线测试，未主动请求真实额度接口验收。

以下 OAuth 请求规则仍适用。最小间隔约束的是同一服务的两轮刷新；必要的令牌续期或组织发现属于同一轮的前置请求，任一步失败即停止。

读本机已有的登录凭据，各发一次 HTTPS 请求，默认每 3 分钟刷新一次当前显示的那个 AI。Claude 的访问令牌过期后，会先续期（见下）再请求。

为了不触发服务端的限流，所有请求都受下面几条约束：

- **最小间隔**：同一家服务两次请求至少隔 2 分钟，不管是定时刷新、切换 AI、打开面板、“立即刷新”还是 `--check`。网络超时也计入间隔，因为服务端可能已经收到请求。请求前先记录等待状态，刚刷新过的时候“立即刷新”是灰的。
- **人不在时降频**：5 分钟没有键盘鼠标操作后，改为 15 分钟刷新一次；一有操作就恢复，数据过期的话立刻补一次。详情面板开着时不降频。
- **被限流或被拒绝后**：至少停 5 分钟，之后逐次加倍，普通退避最长 16 分钟；`Retry-After` 支持秒数和标准 HTTP 日期，不截短服务端要求的等待。等待时间和退避进度会记在缓存文件里；重启程序、从睡眠唤醒、点“立即刷新”都不能让它提前结束。
- **请求标识**：查 Claude 时自称 `claude-code/版本号`，版本号取本机 Claude 桌面端自带的 Claude Code 版本（`%APPDATA%\Claude\claude-code` 下的文件夹名）。这个接口本来是给 Claude Code 用的，同类工具都这么做；这等于冒充官方客户端，是有意的选择。查 Codex 时用的是自己的名字 `iusage/版本号`。

| | 凭据文件 | 接口 |
|---|---|---|
| Claude | `~/.claude/.credentials.json` | `api.anthropic.com/api/oauth/usage` |
| Codex | `~/.codex/auth.json` | `chatgpt.com/backend-api/wham/usage` |

Mac 版的接口相同，凭据来源不同：Claude 读登录钥匙串里的 `Claude Code-credentials` 条目，没有时才回退到 `~/.claude/.credentials.json`；Codex 按其配置读文件或钥匙串（`file` / `keyring` / `auto`；较新官方版本的 `secrets` 加密后端暂不支持）。读取一律不弹授权框。

- **Claude 令牌续期**：只在访问令牌已经过期时才做，请求和 Claude Code 自己续期时发的一样：向 `platform.claude.com/v1/oauth/token` 提交文件里的刷新令牌、Claude Code 的 `client_id` 和原有的 scope。成功后把新令牌写回 `~/.claude/.credentials.json`，只替换 `accessToken`、`refreshToken`、`expiresAt`（有则同时替换 `refreshTokenExpiresAt`）四个值，文件其余字节原样保留；写入前会重新解析，结果和预期不一致就不写；写入用临时文件替换。
  - 服务端可能在续期时换发新的刷新令牌，旧的随即作废，所以任何可能写不回去的情况都在请求**之前**检查：文件只读、目录不可写、文件结构异常（如重复键），都直接报 `无法保存`，不发请求。
  - 请求返回后会再读一次文件；如果里面的刷新令牌已经不是用的那个（Claude Code 同时续期了），保留对方的文件，不覆盖。
  - 刷新令牌被服务端拒绝后，按上面的规则等待（至少 5 分钟，等待记在缓存里，重启不能绕过）；之后同一个令牌不再提交，直到文件里换成新的。程序重启会让这条记忆清空，等待结束后再试一次。
  - 续期请求也受上面的最小间隔和退避约束，失败不会连续重试。
  - 只有 Claude 会续期；Codex 的令牌仍然只读。
- 其余情况凭据只读，不写日志。令牌只发往三个官方域名：`api.anthropic.com`、`platform.claude.com`（仅续期）、`chatgpt.com`。
- 这些接口都不是公开文档里的接口，官方改动后可能失效。
- 网络走系统代理。
- 请求不跟随重定向，token 不会被带到这三个域名之外；证书由系统校验。
- 程序不含任何统计、上报或自动更新，二进制里只有上面三个域名。

## 安全上要知道的

- Windows：exe 没有代码签名，拷到别的电脑上运行会被 SmartScreen 拦一下。
- Windows：exe 放在哪个文件夹，就会优先从那个文件夹加载同名的系统库。所以它应该放在只有你自己能写的本地文件夹里，不要放在会被同步或共享的位置。
- Mac：app 只有本机 ad-hoc 签名，没有公证；拷到别的 Mac 上会被 Gatekeeper 拦下，请在那台机器上自行构建。
- 和所有同类工具一样，它读的是官方客户端的登录凭据；能以你的身份运行程序的东西，本来也能读到这些文件。Claude 的续期还会改写这个文件，并让旧的刷新令牌作废；如果你同时在用别的工具读同一个文件，它们会读到新令牌，持有旧令牌副本的工具则需要重新读取。
- Mac 上 Claude 的凭据通常在钥匙串里而不是这个文件；Mac 版的续期规则与这里共用，写回读取它的同一个位置（钥匙串或文件）。请求前会先确认写得回去，写不回就不发请求，旧刷新令牌保持有效，细节见 `macos/README.md`。

## 构建

需要 Rust。用 `stable-x86_64-pc-windows-gnu` 工具链即可，不需要 Visual Studio。

```
cargo build --release
cargo test
```

- 构建结果是 `target/release/iusage.exe`。
- 应用图标在 `assets/iusage.ico`，包含 16–256 像素的七种尺寸，构建时与原有 DPI 清单一起嵌入；只增加约 19 KiB。`assets/iusage.svg` 是矢量设计，`assets/generate-icon.ps1` 可离线重新生成 ICO，不需要安装资源编译器。托盘仍显示动态用量条。
- 如果源码放在会被同步的文件夹里（OneDrive 等），先在自己的 cargo 配置里把 `target-dir` 指到同步范围之外，否则编译产物会被全部上传。Windows 上是 `%USERPROFILE%\.cargo\config.toml`，macOS 上是 `~/.cargo/config.toml`。项目里的 `.cargo/config.toml` 只有这段说明，没有设置。
- 依赖库的源码路径会被编译进 exe，其中带着你的系统用户名。要发布 exe 的话，在同一个 cargo 配置里加 `rustflags = ["--remap-path-prefix=<你的用户目录>\\.cargo=cargo"]` 去掉它。
- 更新已安装的版本：先退出正在运行的程序，再用新的 exe 覆盖旧的，然后重新启动。
- `iusage.exe --check > out.txt` 用于排查：正式程序运行时不另发请求；否则优先使用新鲜缓存，并跳过冷却中的服务。确需刷新时才请求，并保存结果和退避状态。开发验证优先使用离线测试，不要连续运行诊断命令或阶段 0 的探测脚本。
- `cargo test --offline` 使用模拟响应，不调用真实用量 API。其中一项测试需要写临时注册表键；受限环境可以使用 `cargo test --offline -- --skip value_round_trips_through_the_registry`，再在允许注册表写入的环境单独执行该项。
### macOS

需要 Xcode 命令行工具和 Rust。构建目录默认在 OneDrive 外（`/private/tmp/iusage-mac-build`）。首次先下载依赖（只访问包仓库），之后全程离线：

```
CARGO_HOME=/private/tmp/iusage-mac-build/cargo-home cargo fetch --manifest-path macos/Core/Cargo.toml
sh macos/scripts/build-prototype.sh
sh macos/scripts/package-local.sh
```

- `build-prototype.sh` 先跑全部离线测试（Rust 共享模块与桥接、Swift 凭据、续期、运行层、网络、协调器，使用模拟钥匙串和模拟 HTTP），通过后才生成 app；不会调用真实用量 API。
- `package-local.sh` 生成 `/private/tmp/iusage-mac-build/release/IUsage.app`：固定 bundle ID、默认启用定时刷新、本机 ad-hoc 签名；只打包和校验签名，不安装也不启动。直接运行构建出的 `IUsage Prototype.app`（不带参数）只显示模拟数据。
- 启动选项：`--cached` 只显示缓存，`--live` 定时刷新真实数据（打包版默认等同 `--live`）。
- 详细的设计、验证记录和未完成事项见 [`macos/README.md`](macos/README.md)。

`src/win/` 之外的代码不依赖 Windows，`macos/Core` 直接按路径复用这些文件，没有复制源码。

## 结构

```
src/
  model.rs      数据模型（Provider、Usage、FetchError）
  providers.rs  凭据位置、请求、响应解析、Claude 令牌续期与写回
  timefmt.rs    时间解析与倒计时格式
  view.rs       把用量数据变成要显示的内容
  settings.rs   设置读写
  cache.rs      最近一次成功数据的落盘与读取
  schedule.rs   什么时候允许发请求（最小间隔、空闲降频）
  json.rs       带深度限制的 JSON 读取
  alert.rs      什么时候该提醒（每个阈值每个窗口一次）
  panel.rs      详情面板要显示的内容
  win/          Windows 实现
    mod.rs      任务栏嵌入窗口、托盘、菜单、轮询
    popup.rs    详情面板的布局与绘制
    autostart.rs 开机自启（当前用户的 Run 注册表项）
    render.rs   绘制（形状自绘，文字用 GDI）
    http.rs     WinHTTP 请求（GET，有请求体时为 POST）
macos/
  Core/         Rust 静态库：复用上面不依赖 Windows 的模块，经 C 接口（include/IUsageCore.h）给 Swift 用
  Credentials/  钥匙串与文件凭据读取、本地凭据问题的状态映射
  Network/      URLSession 请求适配器、请求协调（先落盘再发送）
  Runtime/      缓存落盘、续期写回、提醒去重、运行状态
  Prototype/    AppKit 菜单栏界面
  *Tests/       离线测试（模拟钥匙串、模拟 HTTP）
  scripts/      构建与本地打包脚本
```

`win/` 以外的 Rust 模块不依赖 Windows，Mac 版通过 `macos/Core` 复用。

## 现状

每个平台各只在一台机器上测过：Windows 11（26200），175% 缩放，深色主题，单显示器，任务栏居中；Mac 是作者的一台 Apple Silicon 机器。

### Windows

已完成并实测：两家数据获取、任务栏嵌入显示、拖动、点击字母切换、托盘图标、单实例、设置持久化、重启后读缓存、限流后的等待、低额度提醒、详情面板、开机自启的勾选。

还没实测：

- Claude 令牌续期对真实服务的一次完整流程（请求格式取自官方客户端，逻辑只用模拟网络测过；开发时不去主动触发真实续期，等令牌自然过期时第一次生效）
- 勾选开机自启后重启电脑
- 人不在时降频（只有规则测试）
- 资源管理器真实重启后的自动恢复（模拟的广播和窗口销毁能恢复）
- 浅色主题下的配色
- 多显示器、睡眠唤醒、连续运行数小时

### macOS

已完成并实测：两家真实数据获取（各经明确授权的一次验证后，改为正常定时刷新）、菜单栏显示、C/X 切换、详情面板、重启后读缓存、单实例、限流等待、本地凭据问题的显示。

还没实测：

- Claude 令牌续期写回钥匙串：逻辑只在模拟钥匙串上测过，系统是否允许写入这条条目还没验证；不允许时会安全失败，显示“已过期 · 凭据无法写回，未自动续期”，不发请求
- 低额度提醒的系统通知权限与横幅、登录时启动（需要装进“应用程序”后人工验收）
- 浅色主题、多显示器、睡眠唤醒、连续运行数小时；CPU / 内存没有可靠测量

还没做：

- Mac 版的公证与可直接分发的安装包（目前只有本机构建 + ad-hoc 签名）
- Codex 的 `secrets` 加密存储后端
- Mac 版没有 `settings.json`，阈值和刷新间隔不能像 Windows 版那样改文件
