# IUsage

在 Windows 11 任务栏上显示 Claude 或 Codex 的用量：上面一条是 5 小时窗口，下面一条是 7 天窗口。

单个 exe，约 425 KiB（含应用图标），无运行时依赖；此前实测常驻内存约 4 MB（私有）。

![任务栏上的进度条](docs/screenshots/claude.png)

![详情面板](docs/screenshots/panel.png)

前提：本机装有 Claude 或 Codex 的桌面端（或 Claude Code / Codex CLI）并已登录。程序读它们留在本机的登录凭据，自己不需要登录。

Claude 要注意：桌面端有自己的登录，不会更新 `~/.claude/.credentials.json`，程序读的是这个文件，它来自 Claude Code 命令行的登录。这个文件里的访问令牌约 8 小时过期，过期后程序会用文件里的刷新令牌自行续期（见“数据来源”）；只有刷新令牌也失效时，才需要在终端运行一次 `claude` 并输入 `/login`。

## 使用

把构建出的 `iusage.exe` 放到一个只有你自己能写的本地文件夹里运行（原因见“安全上要知道的”）。

- **切换 AI**：点击进度条左边的字母（橙色 `C` = Claude，蓝色 `X` = Codex），或右键菜单里选。
- **详情面板**：左键点进度条（字母和手柄以外的地方）或托盘图标。面板同时列出 Claude 和 Codex，带精确的重置时间和数据的新旧；再点一次、点别处或按 Esc 关闭。面板开着的时候，另一个 AI 的数据如果过期了也会顺带刷新。
- **移动位置**：按住最左侧的点阵手柄横向拖动，位置会记住。
- **右键菜单**：切换 AI、显示已用 / 显示剩余、立即刷新、低额度提醒、开机自启、退出。
- **低额度提醒**：当前显示的那个 AI，已用量到 75% 和 90% 时各弹一次系统通知；同一个窗口内不重复，窗口重置后重新生效。默认开启，在右键菜单里关。
- **开机自启**：在右键菜单里勾选。它记录的是 exe 当前所在的路径；移动 exe 之后勾选会消失，重新勾一次即可。
- **托盘图标**：同样的两条进度条，鼠标悬停看摘要，左键开详情面板，右键出菜单；任务栏嵌入失败时靠它兜底。
- 进度条颜色按已用量变化：75% 起变黄，90% 起变红。
- 右侧文字是“百分比 + 距离重置的时间”，例如 `13% 4h`。

状态文字：

| 显示 | 含义 |
|---|---|
| `…` | 正在取数据 |
| `未登录` | 没找到登录信息，需要先登录对应的客户端（Claude 要登录 Claude Code 命令行） |
| `已过期` | 登录已过期且无法自动续期（没有刷新令牌、刷新令牌也过期，或被服务端拒绝）。Claude：在终端运行 `claude` 并输入 `/login`；Codex：在 Codex 里重新登录。换了新登录后，一般几秒内自动恢复；如果刚被服务端拒绝过，要先等完 5 分钟的退避 |
| `无法保存` | 续期成功，但写不回 `~/.claude/.credentials.json`（只读或被占用）。检查文件权限；程序在请求前就会检查，所以不会白白用掉刷新令牌 |
| `离线` | 网络不通，检查代理 |
| `限流` | 请求太频繁被服务端拒绝（HTTP 429），至少等 5 分钟后自动重试；这期间“立即刷新”是灰的 |
| `HTTP 5xx` 等 | 服务端返回了其他错误码，自动重试 |
| `错误` | 返回内容无法识别，多半是接口变了 |
| 整体变暗 | 最近一次刷新失败，显示的是之前的数据。其中已经重置过的窗口不再显示 `0%`（重置后用没用过是不知道的），而是显示当时的错误状态 |

出错后会自动重试。普通网络/服务错误的退避从 30 秒起逐次加倍，但实际请求仍至少间隔 2 分钟；限流或凭据被服务端拒绝时按 5、10、16 分钟退避。服务端要求更长等待时优先遵守，最多 1 小时。只有本地凭据缺失，或过期而又无法续期时，才每 15 秒重新检查文件，不发送请求。

`%APPDATA%\IUsage\` 下有三个文件：

- `settings.json`：设置。其中 `warn_pct`（默认 75）和 `crit_pct`（默认 90）是变黄 / 变红和提醒的阈值，`poll_secs`（默认 180，最小 30）是刷新间隔，这三项没有菜单，直接改文件后重启程序生效。刷新间隔不建议调小：Claude 的接口会限流，一旦触发要十分钟以上才恢复。
- `cache.json`：两家各自最近一次成功取到的数据、提醒记录、请求时间和退避状态。重启后先显示缓存；新数据和仍未结束的等待均会阻止重复请求。缓存和设置采用临时文件替换，避免写到一半损坏原文件。
- `last-error.txt`：最近记录的失败原因；相同错误不重复写入，文件修改时间是这条错误最近一次被写入的时间。

## 数据来源

读本机已有的登录凭据，各发一次 HTTPS 请求，默认每 3 分钟刷新一次当前显示的那个 AI。Claude 的访问令牌过期后，会先续期（见下）再请求。

为了不触发服务端的限流，所有请求都受下面几条约束：

- **最小间隔**：同一家服务两次请求至少隔 2 分钟，不管是定时刷新、切换 AI、打开面板、“立即刷新”还是 `--check`。网络超时也计入间隔，因为服务端可能已经收到请求。请求前先记录等待状态，刚刷新过的时候“立即刷新”是灰的。
- **人不在时降频**：5 分钟没有键盘鼠标操作后，改为 15 分钟刷新一次；一有操作就恢复，数据过期的话立刻补一次。详情面板开着时不降频。
- **被限流或被拒绝后**：至少停 5 分钟，之后逐次加倍，普通退避最长 16 分钟；`Retry-After` 支持秒数和标准 HTTP 日期，最多等待 1 小时。等待时间和退避进度会记在缓存文件里；重启程序、从睡眠唤醒、点“立即刷新”都不能让它提前结束。
- **请求标识**：查 Claude 时自称 `claude-code/版本号`，版本号取本机 Claude 桌面端自带的 Claude Code 版本（`%APPDATA%\Claude\claude-code` 下的文件夹名）。这个接口本来是给 Claude Code 用的，同类工具都这么做；这等于冒充官方客户端，是有意的选择。查 Codex 时用的是自己的名字 `iusage/版本号`。

| | 凭据文件 | 接口 |
|---|---|---|
| Claude | `~/.claude/.credentials.json` | `api.anthropic.com/api/oauth/usage` |
| Codex | `~/.codex/auth.json` | `chatgpt.com/backend-api/wham/usage` |

- **Claude 令牌续期**：只在访问令牌已经过期时才做，请求和 Claude Code 自己续期时发的一样：向 `platform.claude.com/v1/oauth/token` 提交文件里的刷新令牌、Claude Code 的 `client_id` 和原有的 scope。成功后把新令牌写回 `~/.claude/.credentials.json`，只替换 `accessToken`、`refreshToken`、`expiresAt`（有则同时替换 `refreshTokenExpiresAt`）四个值，文件其余字节原样保留；写入前会重新解析，结果和预期不一致就不写；写入用临时文件替换。
  - 服务端可能在续期时换发新的刷新令牌，旧的随即作废，所以任何可能写不回去的情况都在请求**之前**检查：文件只读、目录不可写、文件结构异常（如重复键），都直接报 `无法保存`，不发请求。
  - 请求返回后会再读一次文件；如果里面的刷新令牌已经不是用的那个（Claude Code 同时续期了），保留对方的文件，不覆盖。
  - 刷新令牌被服务端拒绝后，按上面的规则等待（至少 5 分钟，等待记在缓存里，重启不能绕过）；之后同一个令牌不再提交，直到文件里换成新的。程序重启会让这条记忆清空，等待结束后再试一次。
  - 续期请求也受上面的最小间隔和退避约束，失败不会连续重试。
  - 只有 Claude 会续期；Codex 的令牌仍然只读。
- 其余情况凭据只读，不写日志。令牌只发往三个官方域名：`api.anthropic.com`、`platform.claude.com`（仅续期）、`chatgpt.com`。
- 这些接口都不是公开文档里的接口，官方改动后可能失效。
- 网络走系统代理。
- 请求不跟随重定向，token 不会被带到这三个域名之外；证书由系统校验。
- 程序不含任何统计、上报或自动更新，二进制里只有上面三个域名。

## 安全上要知道的

- exe 没有代码签名，拷到别的电脑上运行会被 SmartScreen 拦一下。
- exe 放在哪个文件夹，就会优先从那个文件夹加载同名的系统库。所以它应该放在只有你自己能写的本地文件夹里，不要放在会被同步或共享的位置。
- 和所有同类工具一样，它读的是官方客户端的登录凭据；能以你的身份运行程序的东西，本来也能读到这些文件。Claude 的续期还会改写这个文件，并让旧的刷新令牌作废；如果你同时在用别的工具读同一个文件，它们会读到新令牌，持有旧令牌副本的工具则需要重新读取。
- Mac 上 Claude 的凭据可能在钥匙串里而不是这个文件；续期只针对文件，Mac 版还没做，到时要单独设计。

## 构建

需要 Rust。用 `stable-x86_64-pc-windows-gnu` 工具链即可，不需要 Visual Studio。

```
cargo build --release
cargo test
```

- 构建结果是 `target/release/iusage.exe`。
- 应用图标在 `assets/iusage.ico`，包含 16–256 像素的七种尺寸，构建时与原有 DPI 清单一起嵌入；只增加约 19 KiB。`assets/iusage.svg` 是矢量设计，`assets/generate-icon.ps1` 可离线重新生成 ICO，不需要安装资源编译器。托盘仍显示动态用量条。
- 如果源码放在会被同步的文件夹里（OneDrive 等），先在自己的 cargo 配置里把 `target-dir` 指到同步范围之外，否则编译产物会被全部上传。Windows 上是 `%USERPROFILE%\.cargo\config.toml`，macOS 上是 `~/.cargo/config.toml`。项目里的 `.cargo/config.toml` 只有这段说明，没有设置。
- 依赖库的源码路径会被编译进 exe，其中带着你的系统用户名。要发布 exe 的话，在同一个 cargo 配置里加 `rustflags = ["--remap-path-prefix=<你的用户目录>\\.cargo=cargo"]` 去掉它。
- 更新已安装的版本：先退出正在运行的程序，再用新的 exe 覆盖旧的，然后重新启动。
- `iusage.exe --check > out.txt` 用于排查：正式程序运行时不另发请求；否则优先使用新鲜缓存，并跳过冷却中的服务。确需刷新时才请求，并保存结果和退避状态。开发验证优先使用离线测试，不要连续运行诊断命令或阶段 0 的探测脚本。
- `cargo test --offline` 使用模拟响应，不调用真实用量 API。其中一项测试需要写临时注册表键；受限环境可以使用 `cargo test --offline -- --skip value_round_trips_through_the_registry`，再在允许注册表写入的环境单独执行该项。
- 目前 `src/win/` 之外的代码不依赖 Windows，但 Mac 的界面部分还没写。

## 结构

```
src/
  model.rs      数据模型（Provider、Usage、FetchError）
  providers.rs  凭据位置、请求、响应解析、Claude 令牌续期与写回
  timefmt.rs    时间解析与倒计时格式
  view.rs       把用量数据变成要显示的内容
  settings.rs   设置读写
  cache.rs      最近一次成功数据的落盘与读取
  schedule.rs   什么时候允许发请求（最小间隔、空闲降频）
  json.rs       带深度限制的 JSON 读取
  alert.rs      什么时候该提醒（每个阈值每个窗口一次）
  panel.rs      详情面板要显示的内容
  win/          Windows 实现
    mod.rs      任务栏嵌入窗口、托盘、菜单、轮询
    popup.rs    详情面板的布局与绘制
    autostart.rs 开机自启（当前用户的 Run 注册表项）
    render.rs   绘制（形状自绘，文字用 GDI）
    http.rs     WinHTTP 请求（GET，有请求体时为 POST）
```

`win/` 以外的部分不依赖 Windows，Mac 版可以直接复用。
