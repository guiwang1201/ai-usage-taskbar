# macOS 菜单栏版

AppKit 菜单栏应用，通过独立 C ABI 复用 `src/` 中的 Rust 核心。打包版（`scripts/package-local.sh`）默认定时刷新真实用量，并支持 Claude 令牌续期；目前只有本机构建和 ad-hoc 签名，没有公证，也不是可直接分发的安装包。用户层面的说明见根目录 [README](../README.md)。

以下是按阶段记录的开发日志，每一节反映当时的状态：较早章节里“使用模拟数据”“尚未接入真实请求”之类的说法已被后面的章节取代，以最后几节为准。不带参数直接运行 `IUsage Prototype.app` 仍只显示模拟数据；`--cached` 只显示缓存，`--live` 或打包版才联网。

## 构建

需要 Xcode 命令行工具和 Rust。首次先下载构建依赖（只访问包仓库，不访问用量 API），后续构建全程离线：

```sh
CARGO_HOME=/private/tmp/iusage-mac-build/cargo-home cargo fetch --manifest-path macos/Core/Cargo.toml
```

项目根目录执行：

```sh
sh macos/scripts/build-prototype.sh
open '/private/tmp/iusage-mac-build/IUsage Prototype.app'
```

默认构建目录在 OneDrive 外。可用 IUSAGE_MAC_BUILD_DIR 指定另一个非同步目录。

原型使用固定模拟数据，通过单次计时器每 180 秒模拟刷新当前服务，没有 HTTP 或凭据读取。菜单栏显示 C/X、5h / 1week、双进度条及已用百分比，可切换服务，点击展开两家详情；面板中可退出。服务选择、模拟用量与冷却状态保存在 ~/Library/Application Support/IUsagePrototype/mock-cache.json，使用独立实例锁。不创建登录启动项。当前构建为本机架构，使用临时签名，未做公证。

## 凭据模块

Credentials/Credentials.swift 使用 Security 和 LocalAuthentication 读取指定钥匙串条目，禁止交互授权。仅条目不存在时尝试 Claude 文件回退；拒绝或锁定不会被当成缺失，也不会自动绕过。凭据不写入文件，不打印；过期检查仅覆盖 Claude 明确提供的 expiresAt，不代表服务端有效性。

Codex 当前仅实现显式文件来源读取，尚未实现 keyring/auto/ephemeral 配置解析和存储选择。不得将此文件探测直接当作正式应用的自动来源选择。

只读本机来源检查工具（不会请求接口）：

```sh
swiftc -warnings-as-errors -module-cache-path /private/tmp/iusage-mac-build/module-cache \
  macos/Credentials/Credentials.swift macos/Probe/main.swift \
  -o /private/tmp/iusage-mac-build/credential-probe
/private/tmp/iusage-mac-build/credential-probe
```

输出只有状态，不能通过该工具判断桌面端是否已登录。沙箱内可能得到不可用错误；不应反复重试或提示用户重新登录。

## 核心桥接阶段

用户已确认首版视觉显示正常。macos/Core 是独立 Cargo 库，通过 path 模块复用 src/ 中的现有 Rust 文件，无源码复制，不修改 Windows 构建入口或依赖。Swift 通过 Core/include/IUsageCore.h 调用响应解析和请求状态方法。原型模拟响应现在也通过 Rust 解析，不再直接将全部用量值写死在视图中。

## Claude 令牌续期：2026-10-02

Claude 访问令牌约 8 小时过期。Mac 版现在和 Windows 版一样，只在令牌已过期时用文件或钥匙串里的刷新令牌自行续期，并把新令牌写回读取它的同一个位置。

**规则与 Windows 完全共用。** 共享 Rust 的续期逻辑拆成与存储无关的两步（`plan_claude_refresh` 检查并生成请求，`finish_claude_refresh` 解释应答并生成要写回的文本），Windows 文件版和 Mac 通过 C ABI 调用同一份代码，没有在 Swift 里重写。包括：只替换 `accessToken`、`refreshToken`、`expiresAt`（有则同时替换 `refreshTokenExpiresAt`）四个值，其余字节原样；被服务端拒绝的刷新令牌不再重复提交，直到存储里换成新的；请求返回后重读存储，若刷新令牌已被别人（Claude Code）换掉就保留对方的。Windows 的 12 项续期测试在拆分后仍全部通过。

**Mac 独有的部分：**

- 凭据来源被记住（钥匙串条目或 `.credentials.json`），续期只写回原来源，不会写到别处。
- 请求前先证明存储可写：文件检查为普通文件（拒绝符号链接）、目录可建新文件；钥匙串把刚读到的字节原样写回一次（写前确认内容没变）。证明失败就**不发请求**，显示“已过期 · 凭据无法写回，未自动续期”，旧刷新令牌保持有效，Claude Code 仍可正常续期。钥匙串写入不允许交互，需要用户批准的写入会失败而不是弹窗。
- 续期算一次对 Claude 的请求，使用同一个持久化闸门：计入至少 90 秒的最小间隔（0.1.8 起，与 Windows 共用 `src/schedule.rs`），被限流（含 Retry-After）或被拒绝后至少等 5 分钟，重启不能绕过。续期成功后，用量请求在一个最小间隔之后发出，而不是紧接着发。
- 续期请求只发往 `platform.claude.com/v1/oauth/token`，传输层的白名单按方法和路径精确匹配（该地址只允许 POST，两个用量地址只允许 GET），不跟随重定向。
- 写回失败（服务端已换发新令牌但存储写不进去）显示“无法保存凭据”，按拒绝处理，至少等 5 分钟；写入尝试 3 次。这一情形靠请求前的证明尽量避免，无法完全消除，与 Windows 相同。
- Codex 令牌仍然只读。

**验证（全部离线）：** 共享 Rust 74 项（含 3 项新增的 ABI 测试）；新增 47 项 Swift 续期检查，使用模拟钥匙串、临时文件夹和模拟传输，覆盖成功、写前先保存闸门、竞态不覆盖、被拒绝不重复提交、限流与网络失败、存储不可写不发请求不预约、写回失败、未过期/中途变化/闸门关闭/缺少客户端版本都不发请求、文件存储的原子替换与 0600 权限、传输白名单；其余原有检查全部通过。**没有对真实 Claude 令牌端点或真实凭据做过任何请求**，开发时也不会去触发：第一次真实续期要等令牌自然过期。

**本机来源（用户在终端运行 `security find-generic-password -s "Claude Code-credentials"` 提供的元数据，不含令牌）：** Claude 凭据在登录钥匙串，服务名 `Claude Code-credentials`，账户为本机用户名，创建于 2026-10-02 10:29:46，修改时间只晚 1 秒，即截至该次查询没有被续期过。所以这台机器上续期走钥匙串写回，不走文件。按约 8 小时有效期，第一次续期约在 18:30 前后。

**尚未验证：** 对这条钥匙串条目做写入是否被系统允许。该命令不显示访问控制，读取一直不弹窗说明读取被允许，但写入是另一回事，只在模拟存储上测过。若不允许，会按上面的方式安全失败，状态显示“已过期 · 凭据无法写回，未自动续期”，此时 Mac 版仍只能等 Claude Code 自己续期。若系统反而弹出授权对话框：同一份过期凭据写入被拒绝后，30 分钟内不再尝试（凭据变化则立即恢复），避免对话框每分钟弹一次；点“拒绝”是安全的，点“始终允许”之后才会自动续期。
