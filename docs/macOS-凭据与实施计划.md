# macOS 凭据与实施计划

日期：2026-10-02。阶段：来源调查与实现规划，尚未实现 Mac 运行入口。

## 产品约定

- 原生菜单栏应用，服务标识 + 上下两条用量进度条，点击显示两家详情。
- 体积小、响应快、低系统占用，不引入 WebView。
- 复用 Rust 数据模型、解析、缓存、调度和提醒规则；平台实现隔离，不改变 Windows 行为。
- 默认只读现有凭据，不接管登录、不刷新 token、不持久保存凭据副本。

## 来源与兼容边界

### Claude

官方文档说明：macOS 优先使用 Keychain；钥匙串写入被拒绝时可回退到 .credentials.json。CLAUDE_CONFIG_DIR 同时影响文件目录与钥匙串条目标识。

本机已安装客户端的静态逻辑也显示服务名由 Claude Code、认证环境后缀、-credentials 和可选目录哈希组成，并涉及 CLAUDE_SECURESTORAGE_CONFIG_DIR。该细节属于本机版本实现，不应当作长期稳定协议。

Mac 适配应支持 Keychain 与文件来源，并按实际客户端规则确定选择顺序。需要区分未找到、钥匙串锁定、拒绝访问、解析失败和凭据过期；后台不能反复触发授权弹窗。普通 Claude 桌面聊天登录是否足够，目前未确认，不能承诺仅安装桌面端就一定可用。

来源：https://code.claude.com/docs/en/authentication

### Codex

官方文档支持 file、keyring、auto 和 ephemeral 凭据存储。file 使用 CODEX_HOME 下的 auth.json；keyring 使用系统凭据存储；auto 优先系统存储并可回退文件；ephemeral 不提供持久凭据。

本机文件来源可作为首版接入路径。完整兼容需要另外核实钥匙串服务名、账号键和路径派生规则，并尊重存储配置，避免误用遗留 auth.json。API key 不等同于当前用量接口所需的订阅 OAuth 登录。

来源：https://learn.chatgpt.com/docs/auth

## 实施顺序与验收

1. **凭据适配离线验证**：新增 Mac 凭据来源层，保留 Windows 现有入口。先做模拟文件与模拟钥匙串测试，覆盖缺失、拒绝、锁定、过期、自定义目录和存储模式。本机 Claude 钥匙串可见性与可读性仍是待验证项；不导出凭据解决它。
2. **原生界面原型**：用模拟数据完成菜单栏双进度条、服务切换和详情面板。原型必须明确离线，不开启用量轮询。验证 Retina、深浅色、点击外部关闭和窄菜单栏显示。
3. **接入运行逻辑**：接入平台 HTTP 与系统代理，复用缓存、请求前落盘、最小间隔和 Retry-After；用模拟 HTTP 验证。缓存放在 Mac 用户应用数据目录，不保存 token。
4. **系统功能与稳定性**：单实例、登录启动、通知、空闲降频、睡眠唤醒、网络变化。面板关闭后停止面板倒计时更新；按下一次必要事件安排唤醒。
5. **打包与回归**：产出原生 .app；构建目录放在 OneDrive 外。测量发布体积、启动耗时、稳定空闲内存、CPU 与唤醒次数，再制定有依据的指标。运行共享离线测试；Windows 专属构建和回归需在具备工具链的环境执行，Mac 测试不能替代。

UI 初步采用 AppKit 菜单栏与原生弹出面板。Rust 直接绑定或薄原生桥接在原型时比较构建复杂度和产物开销，不引入 WebView。Intel 与 Apple Silicon 的发布范围在打包阶段确定。

真实 API 验证仅在离线测试完成且凭据可用后进行最少量端到端检查，继续遵守缓存和冷却；不运行循环诊断。
